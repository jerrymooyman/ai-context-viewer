# Saved snapshot files

`$snapshot-session` reports the current task; the export helper validates and saves one immutable file under `<canonical-project>/.session-snapshots/`. Refresh collects saved files. No watcher or model request runs in the viewer.

The complete [envelope example](../skills/snapshot-session/references/envelope-example.json) is checked by the real validator. It contains exactly seven fields:

| Field | Meaning |
|---|---|
| `envelope_version` | Integer `1` |
| `project_root` | Absolute canonical project root; descendants/worktrees are separate |
| `session_id` | Explicit current Codex identity; never newest-log inference |
| `task_ref` | Canonical progress-document path, or `null` for Unassigned task |
| `context_binding` | Initial or explicit manual binding below |
| `exported_at` | ISO timestamp generated by the helper; does not order history |
| `snapshot` | Strict [schema v1](snapshot-schema.md) payload, complete `scope: "goal"` |

Initial binding is `{"version":1,"kind":"initial"}`. A manual binding has exactly `version: 1`, `kind: "manual"`, `context_id`, `generation`, and `boundary_record_key`; use the viewer's copyable context target. Once any viewer boundaries exist, even an initial target needs an explicit binding. Bindings are rechecked against the same sidecar and current log generation. Stale/unmatched histories remain unresolved without borrowed evidence.

## Export helper

Use `ai-context-viewer --export-snapshot --help` after installation, or `python3 /path/to/ai-context-viewer/scripts/ai-context-viewer --export-snapshot --help` from source.

```text
--inspect + explicit project/session/task/binding
  → target + attachment + head + goal_id
full semantic input + --expected-head none|ID + same route
  → validate → lock/recheck → generate ID → immutable publication
```

Input has every schema-v1 field **except `snapshot_id`**; see [semantic input](../skills/snapshot-session/references/report-format.md). For the first report `supersedes` is null. Later input preserves inspected `goal_id` and supersedes the exact head. A stale prepared report is rejected; inspect again and rebuild the report. Code generates `snapshot_id`, export time, canonical routing metadata and safe filenames. Paths/IDs supplied by the agent never become filenames. Omit `--task-ref` when unknown; the helper does not read task documents or infer a task.

The launcher uses the application's `.local/state.json` for both viewer and exporter by default. Pass the same `--state-file` to both when overridden. The standalone `python3 -m viewer.export_snapshot` defaults to `<project>/.local/state.json`; when using it directly, supply the viewer's actual sidecar. Log root defaults to `$CODEX_HOME/sessions` or `~/.codex/sessions`. An explicit ID without matching metadata may save an unresolved report; duplicate identities or a different recorded project produce an error.

Publication uses an OS advisory lock, same-directory temporary file, flush/fsync and no-clobber link. Never break a lock by age. An error after publication may name an existing report with uncertain durability; inspect before retrying. Export establishes the exact project-local `/.session-snapshots/` Git ignore entry without replacing other rules. No Codex log writes occur.

## Collection, persistence and limits

Histories are keyed by project + session + context binding + task reference. Same-task fresh chats group together without sharing understanding. Task switches and path renames select separate histories; returning selects the original. File and log/import streams have separate ancestry. Matching ID and canonical payload can link provenance; differing payloads are conflicts.

The collector validates complete bounded scans and walks ancestry, collapsing canonical duplicates. Ambiguous roots, branches, conflicting IDs or missing parents stop advancement. Enumeration and timestamps cannot choose a winner. The SQLite ledger beside the configured JSON sidecar stores accepted canonical bytes and decisions: `state.json` uses `state.snapshots.sqlite3`. Deletion/mutation of an accepted export retains its cached bytes with a warning, including after restart. Corrupt/unwritable storage prevents advancement and never resets itself.

| Limit | Behavior |
|---|---|
| Payload 64 KiB; envelope 96 KiB | Invalid/oversized report rejected |
| 10,000 candidates / 256 MiB per project scan | Incomplete scan retains committed state; malformed files count |
| 100 history entries per page | Current head is independent of the page; files can advance past 128 reports |
| 100 diagnostic messages / 512 characters each | Total diagnostic count retained |

Stop the service before backing up **both** the JSON sidecar and SQLite ledger. Restore them together with matching logs/exports. Removing the ledger intentionally reconstructs from remaining unambiguous exports and loses retained bytes/acceptance decisions absent from those files. No automatic pruning, repair or deletion exists. Browser imports remain memory-only; file exports and accepted ledger history are durable.
