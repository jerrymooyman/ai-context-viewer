---
name: snapshot-session
description: Save a complete current-task understanding report for ai-context-viewer. Use only when explicitly invoked by the user.
---

Save one complete goal report for the current conversation, then give a short save confirmation reminding the user to Refresh the viewer. This is agent self-report; unknown coverage stays unknown. Do not send messages, edit sources/logs, install anything or emit a second marked snapshot into the conversation.

1. Identify the exact project root from the current task, normally the launch directory. Identify its explicit progress-document reference through the known handoff/progress relationship. If none is known, omit `--task-ref` (Unassigned task); do not guess from newest files, directory or another task's pointer.
2. Require the **current client's explicit session ID** supplied by an explicitly verified client identity source, or by the user from the current client's status display if it exposes the chat ID. Environment IDs alone are unverified candidates. Never choose the newest log, use an ancestor/subagent's ID or infer identity from the project. If the ID is unavailable, stop and ask the user to provide the current chat ID. Do not guess.
3. Invoke `ai-context-viewer --export-snapshot --inspect --project <root> --session-id <explicit-id>` with `--task-ref <progress-path>` when known. Use the viewer's exact `--state-file` and `--log-root` settings if overridden. The launcher gives viewer and helper the same default application sidecar; the standalone Python helper has a different project-local default. Keep the same routing options for export. This helper checks exact recorded ID/directory and rejects ambiguity. An unmatched explicit ID may save an unresolved file, with no evidence attachment; say so in the confirmation. Unsupported adapters retain metadata only.
4. If inspection says boundaries exist, request the copyable context target from the selected viewer context. Pass its `context_binding` as JSON using `--context-binding`; verify its session/project agree with this conversation. Do not choose the initial/latest boundary yourself. A stale target requires a new copy from the viewer.
5. Read [references/report-format.md](references/report-format.md). Build a full current report, including every intended subtask, shared constraint, assumption, decision, unresolved question and known source. Use the inspected `goal_id` and `head` as `goal_id` and `supersedes`; on a new history choose a stable goal ID and use null ancestry. Do not generate `snapshot_id`, timestamps or envelope metadata. Do not invent evidence keys, source reads, successful checks or certainty. Known source titles may have empty evidence keys and remain unresolved. Only report verification actually observed in this context; otherwise use `unknown`.
6. Feed that JSON to `ai-context-viewer --export-snapshot` with the same routing options, `--input -` and `--expected-head <inspected-head-or-none>`. Use a quoted heredoc or tool stdin so report content cannot execute as shell code. The helper generates identity/ancestry metadata and publishes one immutable file. A stale-head error requires a fresh inspection and rebuilding current semantic content; do not silently rewrite ancestry or retry in a loop. Stop on other errors and show the actionable helper error. If publication durability is uncertain, inspect the named file before any retry.

Do not import old session understanding automatically. A fresh chat starts its own history even when it identifies the same progress document. Task switches select a separate history; returning selects that task's existing history. Refresh collects files and never asks a model for a report. A bare `/snapshot-session` alias is not promised.
